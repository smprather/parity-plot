# Bug scan — 2026-09-26

Scope: whole `parity_plot` package plus the uncommitted NFS/offload work
(`designer/io.py`, async data panel, async `refresh`). The full suite (785) and
`./check-tier-1` pass on the working tree; none of the items below is caught by
them.

Evidence tags: **[repro]** reproduced with a script (in the session scratchpad),
**[code]** confirmed by reading the code path end to end, **[plausible]** likely
but not exercised.

## P0 — broken in the working tree

- [ ] **Non-data panels never refresh or auto-save.** [repro]
  `app.py:339-343` now passes the *async* `refresh` straight to the tolerance,
  polynomial, histogram, encoding and controls panels, and `build_table` gets
  `lambda: refresh()`. Every one of those panels calls `on_change()` from a
  *sync* commit and drops the result (`controls.py:259,265,315`,
  `tolerances.py:44`, `polynomial_lines.py:30`, `histogram.py:115`,
  `encoding.py:45`, `table.py:53`). The coroutine is created and garbage
  collected: plot not redrawn, status bar not updated, **edits not auto-saved**
  (only `RuntimeWarning: coroutine 'refresh' was never awaited` in the log).
  At HEAD `refresh` was sync, so this is a regression.
  - Fix: hand sync panels a scheduler, e.g. `schedule_refresh = _awaitable(refresh)`
    (already used for brushing), or make the panels' commits `async` and
    `await on_change()`.
  - Test: add `filterwarnings = ["error::RuntimeWarning"]` to pytest config, and
    a test that drives a panel commit with an async `on_change` and asserts it
    ran.

- [ ] **Add File fans out into ~6 full reads of every open CSV.** [repro + code]
  This is what still hangs on NFS. `refresh_options` raises `_suspend`, assigns
  `ref_sel.value`/`test_sel.value`, then lowers it *before any await*
  (`data_panel.py:239-245`). NiceGUI runs async `on_change` handlers as
  background tasks (`nicegui/events.py:475`), so each `_reapply`/`apply()` body
  runs after the guard is already down (repro: the guarded `apply` ran). One
  Add File with ref/test unset gives 1 `column_options` read, plus 2 × (`column_options` +
  `load`) from the spurious `_reapply` tasks, plus the final `apply()` load.
  That's six full reads of every open file, running concurrently in the thread
  pool, each followed by its own `refresh` + auto-save. `ChoiceElement.update()`
  also resets a now-invalid select value to `None` (`s.update()` at
  `data_panel.py:246-247`, outside the guard), which fires yet more applies.
  - Fix: guard synchronously, before spawning. Wrap the handlers as
    `lambda: None if _suspend["v"] else background_tasks.create(apply())`,
    or set values without events (`set_value` inside a `_props` suspension /
    `element._props[...]`). Then coalesce: one in-flight commit per panel,
    and "latest request wins" (below).

- [ ] **Edits made during a slow load are silently reverted.** [repro]
  `DesignerState.set_data_source` now runs in a worker thread. It snapshots
  `self.config.merge(data=…)` at start (`state.py:91`), sits in `load()` for
  the NFS read, then assigns `self.config = candidate` (`state.py:122`). Any
  plot/stats edit made on the loop meanwhile is overwritten. Repro: retitle
  during a 0.5 s load, title reverts to "Parity Plot". The widget still shows
  the edit and the next auto-save writes the config without it.

- [ ] **Opening another config during an in-flight load overwrites the newly
  opened file with the old design.** [code — same mechanism as above]
  The old panel's thread finishes after `_swap` → `state.config` becomes the
  *old* config + data change → `await on_change()` → `refresh()` auto-saves it to
  `sess["session"].config_path`, which is now the *new* file.

- [ ] **Out-of-order loads: an older slow load beats a newer choice.** [repro]
  Pick test=B (slow), then test=C (fast): state ends on B while the select
  shows C.
  - Fix for the three items above: split `set_data_source` into a pure
    `prepare(values) -> (candidate_data_section, ParityData)` run in the thread,
    and a `commit()` on the loop that (a) drops the result if a generation
    counter moved (bump it on every apply and on `_swap`/`load_session_config`),
    and (b) merges **only the `data` section** into the *current* config. Keep
    the "keep previous dataset on failure" rule in `commit`.

## P1 — NFS: blocking I/O still on the event loop

- [ ] **Data panel build reads every CSV synchronously.** [code]
  `build_data_panel` calls `column_options(...)` directly
  (`data_panel.py:124`), and `open_sources` reads each file in full. This runs
  on every page load and every config swap (`settings_column.refresh()`,
  `app.py:435`). A reconnect that outlasts NiceGUI's reconnect timeout
  reloads the page and does it again, which can cascade.
  - Fix: build the selects with just their current values as options, then
    spawn the async `refresh_options()`; and cache `open_sources` per
    `(path, st_mtime_ns, st_size)`. The cache also halves the reads of every
    ref/test change, which today does `column_options` + `load`.

- [ ] **Config picker parses every `*.toml` in the launch dir on the loop.**
  [code] `choice_options()` → `config_choices()` in `page()` (`app.py:349`) and
  `_sync_picker()` (`app.py:424`, after every open / Save As / failed open).
  - Fix: offload, and cache by mtime; or list by glob and validate on open.

- [ ] **Auto-save does 3–4 NFS round trips per refresh while holding
  `_refresh_lock`.** [code] (`exists`, `read_text`, `mkdir`, `write_text`,
  `session.py:106-109`; `app.py:317`). Refreshes queue behind each write, and
  filter/brush refreshes re-save an **unchanged** config. Typing in a text
  control serialises one NFS write per keystroke.
  - Fix: skip when `not s.is_dirty(state.config)`; debounce (~300–500 ms,
    last-wins); reuse `disk_text` instead of re-reading unless mtime changed;
    do the write outside the refresh lock.

- [ ] **Auto-save failure is invisible and aborts the refresh.** [code]
  An `OSError` from the offloaded save (NFS timeout, `ESTALE`, `EACCES`)
  propagates out of `refresh()` *after* the status bar was painted "Ready";
  `refresh_inspector()`/`refresh_table()` never run; the error is only in the
  server log.
  - Fix: catch `OSError` around the save → `⛔ Auto-save failed: …`; refresh
    the views before saving.

- [ ] **Config writes are not atomic.** [code] `Path.write_text` truncates then
  writes (`session.py:109`). An NFS timeout, crash or concurrent reader (another
  tab's picker, the CLI) can see an empty/partial TOML, and concurrent saves
  (Save As vs auto-save, two tabs) can interleave.
  - Fix: write a temp file in the same directory + `os.replace`; one
    process-wide save lock.

- [ ] **Large files: parsing is GIL-bound Python in 1–6 concurrent threads.**
  [plausible] `open_sources`/`load` build per-row dicts in Python; several
  parse threads plus `state.figure()`/`record_views` on the loop can still
  starve the heartbeat on big CSVs even with I/O offloaded. Fixing the fan-out
  and adding the cache above is most of the cure; consider `run.cpu_bound` for
  the load if it persists (check with `--debug` timings).

## P1 — correctness / robustness

- [ ] **Designer page returns HTTP 500 when a configured value is not among
  the select options.** [code + repro of the option gap]
  `ui.select(options, value=…)` raises `ValueError: Invalid value` at
  construction (`nicegui/elements/choice_element.py:22`). This hits the
  ref/test/join/colour selects in `build_data_panel` when:
  - any open file is briefly unreadable on NFS: `column_options` swallows
    `DataError` and returns *all-empty* options.
  - `ref`/`test` use the path form (`/dir/w.csv:a`). `load` accepts it, but the
    options only offer `w.csv:a` (repro).
  - two open files share a basename. The options list `data.csv:x` twice and
    picking one raises "ambiguous file".
  - the ref column is all-NA. `_require_numeric` passes it, but `_is_numeric`
    needs at least one number.
  - Fix: always include the current value in its select's options; emit
    option names in the same form the resolver accepts (full path when a
    basename repeats, as `hover_labels_for` already does).

- [ ] **Non-UTF-8 or malformed CSVs escape as raw exceptions.** [repro]
  `_read_rows` (`data.py:667`) wraps only `OSError`; `UnicodeDecodeError` and
  `csv.Error` (e.g. "field larger than field limit") escape. The CLI then
  prints `'utf-8' codec can't decode byte 0xe9…` with no file name.
  `column_options` catches only `DataError`, so after Add File the
  `refresh_options` task dies: the file is listed, nothing loads, and there is
  no status message. At panel build it's a 500. `datasets.peek`/`preview`
  have the same gap, and the preview dialog renders blank.
  - Fix: catch `(UnicodeDecodeError, csv.Error)` in all three readers →
    `DataError(f"{path}: not UTF-8 text …")`.

- [ ] **File browser only handles `NotADirectoryError`.** [code]
  `_browse.show()` (`data_panel.py:494-498`): `PermissionError`, a removed
  directory, or NFS `ESTALE` kills the task; the dialog stays on the old
  listing with no message.
  - Fix: catch `OSError`, show it inline in the dialog, keep the previous cwd.

- [ ] **Symlinked CSVs and directories are invisible in the browser.** [code]
  `filebrowser.py:45,49` classify with `follow_symlinks=False`, so a symlink
  is neither dir nor file and is dropped. Common in NFS project layouts.
  - Fix: follow symlinks for classification, with `try/except OSError` for
    dangling links. The extra stat is off-loop now.

- [ ] **`color_column` lets `inf`/`nan` through.** [repro]
  `_require_numeric` accepts `"inf"` (`float()` parses it) and `_color_value`
  (`data.py:243`) doesn't filter it: `color_values == [inf, 5.0]`. This breaks
  the finite-data convention. `_is_numeric` has the same leniency when
  offering columns.
  - Fix: route colour cells through the same finite check as `_parse`
    (NaN → None, inf → `DataError`).

## P2 — medium / low

- [ ] **Multiple tabs share one `DesignerState`/`Session`, but each tab has its
  own `_refresh_lock`, widgets and `files` list.** [code] An edit in tab A
  doesn't repaint tab B, and tab B's next data edit re-commits its stale file
  list over A's.
  - Fix: an app-level lock plus a refresh broadcast to all clients, or
    per-client state.
- [ ] **Two quick config picks race.** [code] Concurrent `_open_named_now`: the
  last to *finish* wins, not the last picked.
  - Fix: the same generation counter as above.
- [ ] **Dialogs and CSS leak.** [code] `_browse`, `_preview_dialog`,
  `confirm_discard` and `ask_where_to_save` create a new `ui.dialog` per open,
  and `close()` only hides it. The preview also calls `ui.add_css` on every open
  (`data_panel.py:386`). The DOM grows over a long session.
  - Fix: `dialog.on("hide", dialog.delete)`; add the CSS once in `page()`.
- [ ] **Preview rows input can stack grids.** [plausible] When the NFS read
  outlasts the 500 ms debounce, two `body.refresh()` runs both clear and then
  append, leaving duplicate grids.
  - Fix: a per-dialog generation check before rendering.
- [ ] **`offload` treats a legitimate `None` return as shutdown**
  (`io.py:88`). [code] Harmless today (no offloaded callable returns None), but
  it's why `refresh` calls `save` instead of `autosave`.
  - Fix: test `core.app.is_stopping` instead of the result value.
